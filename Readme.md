### 1. Project Configuration & Tech Stack
- Framework: ASP.NET Core Minimal API (Web API template)
- Database ORM: Entity Framework Core (EF Core) with PostgreSQL provider (Npgsql.EntityFrameworkCore.PostgreSQL)
- Authentication: Microsoft.AspNetCore.Authentication.JwtBearer (validating JWT tokens generated by Supabase Auth)
- Containerisation: A multi-stage Dockerfile optimized for Render deployment

### 5. Detailed Minimal API Endpoints (MapGroup)
Implement the following endpoints using ASP.NET Core Minimal API routing. Write optimized, asynchronous, and robust handler methods with complete try-catch blocks and appropriate HTTP status responses (200 OK, 201 Created, 400 BadRequest, 401 Unauthorized, 403 Forbidden, 404 NotFound).

#### Group: `/api/v1/profiles` (Admin Only)
- **POST `/`**: Creates a new user profile.
- **GET `/`**: Retrieves all user profiles (with optional query parameter `?role=...`).
- **PATCH `/{id}`**: Modifies a profile. If `"is_active": false` is passed, simulate or trigger account deactivation.
- **DELETE `/{id}`**: Removes a user profile (cascading cleanup).

#### Group: `/api/v1/sites` (Admin / Foreman Access)
- **POST `/`** (Admin Only): Registers a new construction site.
- **GET `/`** (Admin and Foreman): Admins get all sites. Foremen are restricted to their assigned sites by joining the `site_foremen` table using their authenticated user ID from claims.
  - *Dynamic Insertion*: Query the `site_updates` table. If today's update is already logged, append a transient `"status": "Submitted ✓"` to the JSON response; otherwise, append `"Needs update"`.
- **PATCH `/{id}`** (Admin Only): Modifies site status or details.
- **DELETE `/{id}`** (Admin Only): Deletes site boundaries.

#### Group: `/api/v1/assignments` (Admin Only)
- **POST `/`**: Maps a foreman to a site inside the `site_foremen` junction table.
- **GET `/`**: Retrieves assignment lists.
- **DELETE `/`**: Removes an assignment (`?site_id=...&foreman_id=...`).

#### Group: `/api/v1/site-updates` (Foreman / Admin Access)
- **POST `/`** (Foreman Only): Submits a daily site update.
  - **Crucial Server-Side Business Logic**:
    1. Check if a record already exists for the given `site_id` on the current date (`DateOnly.FromDateTime(DateTime.UtcNow)`).
    2. **Same-Day Override**: If it exists, update/overwrite the existing record with the new payload fields. Do not duplicate.
    3. **Calculations**: Automatically calculate `actual_labor = bricklayers + plasterers + pavers`.
    4. **Variance**: Automatically calculate `variance = actual_labor - forecasted_labor`.
    5. Save or update the record in the database.
- **GET `/`** (Admin and Foreman): Retrieves updates. Foremen only see updates for their assigned sites. Admins can filter by date-range (`?start_date=...&end_date=...`) or `?site_id=...`.

#### Group: `/api/v1/truck-logs` (Driver / Admin Access)
- **POST `/`** (Driver Only): Submits a haulage trip.
  - **Crucial Server-Side Business Logic**:
    1. **Validation**: Assert that `mileage_after` >= `mileage_before`. If invalid, return a `400 Bad Request` reading "Ending mileage cannot be less than starting mileage".
    2. **Calculations**: Calculate `distance_driven_km = mileage_after - mileage_before`.
    3. **Driver Bind**: Query the `profiles` table to find the user's name matching the authenticated ID, and automatically populate the `driver_name` field.
- **GET `/`** (Admin and Driver): Admins can view all logs; drivers are restricted to their own history via JWT claims.
